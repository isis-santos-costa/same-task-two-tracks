Core profile boils down field information by class:

  • For numerical fields (stock_quantity, price), it informs on central tendency and dispersion via core distribution (min/max: q0/100, median: q50, interquartile ends: q25/75), average, and—for non-date fields—outliers range and count, plus, in the Data Profiling v3+, a robust coefficient of variation [1].

  • For low-cardinality fields (product_id, product_name, category, date_added)—with up to 10 categories— it breaks down the values count for each category, shedding light onto consistency, distribution, and balance.

  • For high-cardinality fields (``), the Core profile is given by uniqueness, as a measure of distinctiveness across entities and of identifier integrity. Primary identifiers (IDs) are expected to be 100% unique. Business identifiers may tolerate a limited % of reuse, e.g., phone number. There are also high-cardinality fields for which uniqueness is expected to be lower, like state.

The Core profile supports anomaly detection such as out-of-bound values or invalid ages or dates.
Numerical field distributions (in v3+) complement this.


Observational Insights


The profile for the raw table reveals some data quality issues:

  • The date format is mixed
  • There is a negative price
  • There is a repeated product ID

The repeated ID happens for the entity with negative price. Processed data standardizes date as ISO and removes this entity.

This is how the processing reviews values for the stock_quantity:

  • Raw: 152.50
  • Processed: 158.33
  • % Difference: +4%

The date fix ensures correct sorting and aggregation. Eliminating duplicate items is important for all metrics.
